# Public site — Women's College Basketball Rosters

The GitHub Pages site for this repository: a searchable roster explorer,
cross-year player pages, and aggregate views of geography, transfers and
season-over-season trends. Hand-written HTML/CSS/JS — no bundler, no Node.

Serves at <https://sports-roster-data.github.io/womens-college-basketball/>
once GitHub Pages is enabled (repo Settings → Pages → Source: **GitHub Actions**).

## Layout

```
site/
  index.html            # shell: one <section> per view; CDN pins (Tabulator 6.3.1, ECharts 6.1.0)
  styles.css            # stone/blue tokens — the palette the roster editor carries inline
  js/
    core.js             # router, data cache, utils, global search, home, about
    roster.js           # season explorer, player cards, team pages
    geography.js        # choropleth, international lines, treemap, hotbeds, in-state % (first four have a Division dropdown)
    transfers.js        # conference/team Sankeys, most-traveled, feeders, turnover
    trends.js           # class years, heights, position mix, roster scale
  data/                 # generated by scripts/build_site_data.R (gitignored)
    us-states.json      # the one committed data file — Census-derived map geometry
```

`transfers.js` is currently **parked**: the transfers view is wired and its
data still builds, but it is deliberately unlinked from the nav and removed
from the router's route list (see the `ROUTES` comment in `core.js`) until
the previous-school adjudication work is finished. To bring it back, load
the script and reopen the section in `index.html`, and re-add `'transfers'`
to `ROUTES`.

The committed CSVs in the repository root are the single source of truth;
the generated JSON under `site/data/` is never committed — the Pages workflow
rebuilds it on every deploy. Design decisions and the reasoning behind each
view are in `docs/plans/2026-10-03-website-design.md`.

## Build

```sh
# requires R + jsonlite; UTF-8 locale per repo convention (non-ASCII literals)
LC_ALL=en_US.UTF-8 Rscript scripts/build_site_data.R
```

The script reads `wbb_rosters_combined.csv`, `players.csv` and `teams.csv`,
runs `stopifnot()` guards (it fails loudly if the CSVs are out of sync —
re-knit `player_ids.Rmd` rather than weakening a guard), and writes all
`site/data/*.json`. Gzip budget: ~7.8 MB total, lazy-loaded per view.

## Preview

Fetches don't work over `file://`, so serve the repo root over HTTP:

```sh
python3 -m http.server 8000
# open http://localhost:8000/site/
```

The `/site/` subpath preview matches how the site is served on GitHub Pages,
which is the case that matters — every asset path in the site is relative.

After editing JS, sanity-check syntax with `node --check site/js/<file>.js`.

## Deploy

`.github/workflows/pages.yml` builds and publishes on push to `main`
(paths-filtered to the site, the build script and the three input CSVs), and
manually via `workflow_dispatch`. One-time setup: repo Settings → Pages →
Source = **GitHub Actions**. Until that is set, deploys fail harmlessly;
re-run the workflow after enabling.

## Annual update

The site hardcodes no seasons. After the annual re-knit commits updated CSVs
(`wbb_rosters_combined.csv` first — see CLAUDE.md for the order), the path
filter triggers a rebuild and the new season appears everywhere, including
the season pickers, at no cost in code changes.
